## 02. 작업 로그

1. **조사** — 채팅 데이터가 세 군데에 분산되어 있음을 확인
   - Firestore `couples/{id}/messages` (본문)
   - Firestore `couples/{id}/files` (첨부 인덱스, 라이브러리 화면이 참조)
   - Storage `couples/{id}/images/**`, `couples/{id}/files/**` (첨부 실물)
   - 한 군데만 지우면 라이브러리 목록이나 직접 URL로 내용이 계속 노출됨
2. **Admin SDK 경로 시도** — `scripts/chat-wipe.ts` 작성(backup/wipe/verify). 서비스 계정 키가 없어 실행 불가로 보류
3. **방향 전환** — 터미널·키 없이 앱 안에서 처리하도록 재설계
4. **보안 규칙 완화** — 클라이언트에서는 자기가 보낸 것만 지워지는 제약을 해소
5. **앱 내 삭제 기능** — 설정 화면에 "채팅 기록 전체 삭제" 추가
6. **점검 모드 1차** — Firestore `adminConfig/maintenance` 플래그 + 관리자 우회
7. **점검 모드 2차** — 로그인 전·연결 끊김 상태에서 점검 화면이 뜨지 않는 문제를 발견해 최상위 게이트로 재구현
8. **배포·병합·정리**

## 04. 구현 결과

✅ 완료 항목

- 채팅 3종(메시지·첨부 인덱스·Storage 실물) 일괄 삭제 기능, 진행률 표시
- 삭제 직후 로컬 IndexedDB 캐시 정리(`purgeFirestoreCacheNow`) + 상대 기기용 1회 퍼지 키 갱신
- 점검 모드 — 로그인 여부·커플 연결 여부와 무관하게 모든 접속 차단
- 관리자 우회 `?bypass=tether-admin` (localStorage 기억), 해제 `?bypass=off`
- v0.26.0 배포 및 라이브 검증

⚠️ 미완료 항목

- **실제 채팅 데이터 삭제** — 되돌릴 수 없는 영구 삭제라 에이전트가 실행하지 않음. 사용자가 앱에서 직접 실행 대기
- **점검 해제** — 삭제 완료 확인 후 `MAINTENANCE_MODE = false` + 재배포 필요

## 05. 특이점 / 결정사항

- **보안 규칙 완화 판단** — 2인 전용 공간이므로 대화 초기화는 양쪽을 모두 지워야 의미가 있다고 보고 `isCoupleMember()`로 완화. 상대방 메시지 개별 삭제도 함께 가능해짐
- **Admin SDK 대신 클라이언트 삭제** — 서비스 계정 키가 없고, 사용자가 터미널 조작을 원하지 않아 앱 내 기능으로 전환. `scripts/chat-wipe.ts`는 키가 생기면 쓸 수 있게 남겨둠
- **점검 게이트를 Provider 위에 둔 이유** — Firestore 기반 플래그는 인증 후에만 읽혀서, 로그아웃·연결 끊김 상태의 접속이 그대로 통과했음. 빌드 상수로 최상위에서 차단하도록 변경
- **차단 범위의 한계** — 앱 화면 레벨 차단이라 SDK 직접 호출까지는 막지 않음. 규칙 레벨 차단은 요청당 조회 증가와 관리자 잠금 위험 때문에 보류
- **우회 값 노출** — `tether-admin`이 클라이언트 번들에 포함됨. 편의 우회 용도로 판단해 그대로 둠
